# iOS iSH Implementation Plan

**Goal:** Prove native iSH execution and implement a safe optional Pi ExecutionEnv when the kernel boundary permits it.

**Architecture:** Pin upstream core outside the committed tree; build its static libraries and exercise guest binaries. Keep experimental native code outside the shipping dependency graph until lifecycle/isolation gates pass.

**Tech Stack:** C, Objective-C, iSH, Meson/Ninja, Python test runner, TypeScript/Pi Durable.

**Spec:** `docs/ios-ish-execution.md`

## Constraints

No host-shell substitution, Node in Hermes, real model calls, unrelated checkout changes, or binary redistribution. Preserve GPL/source obligations. One global upstream kernel is not one isolated instance per conversation.

## Review focus

Host-process exit; guest-root host access; background descendants; unbounded output; interrupted command replay. These require native evidence before enabling product integration.

## Tasks

- [x] Write executable feasibility assertions first: guest shell, streams/status, persistence, fork, argv/cwd/env, bounded host timeout.
- [x] Observe failure without a built guest kernel, then build pinned upstream and add the minimum native entrypoint needed.
- [x] Build/run a standalone simulator application with the same core; record evidence and differences from host execution.
- [x] Evaluate supervisor, credentials, filesystem isolation, cancellation and recovery before connecting Pi ExecutionEnv. Unresolved gates leave the product disabled and are enumerated in draft PR #7.
